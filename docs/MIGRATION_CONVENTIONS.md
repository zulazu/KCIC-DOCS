# KCIC Docs — Migration Conventions

- Tool: Flyway (`backend/src/main/resources/db/migration`).
- Naming: `V<sequence>__<domain>_<description>.sql` (e.g. `V2__identity_users.sql`). Released migrations are immutable; fixes require a new migration.
- Schema namespaces follow `SCHEMA.md`: `identity`, `organization`, `authorization`, `master`, `repository`, `workflow`, `distribution`, `template`, `notification`, `audit`.
- Every migration is written to run on an empty database and in order on an existing database. Destructive changes are not combined with dependent code changes.
- Seed data lives in versioned, idempotent migrations using `INSERT ... ON CONFLICT DO NOTHING`.
- Primary keys are UUIDs generated by the application (`UUID.randomUUID()`); timestamps are `TIMESTAMPTZ NOT NULL` stored in UTC.
- Constraints are explicit: FKs, CHECKs, unique indexes, partial unique indexes (one `CURRENT` document version, one active owner row, case-insensitive username/email/codes).
- Enum-like values are `VARCHAR` + `CHECK`, matching `SCHEMA.md` §14.
- Binary content never enters PostgreSQL; only storage metadata is persisted.
- Spring Session JDBC tables are created by Flyway in the `public` schema using the library’s official PostgreSQL DDL.
- Each schema change requires the matching entity mapping, DTO, tests, and documentation update.
- Bootstrap administrator is **not** seeded in SQL. It is created once at startup from `KCIC_BOOTSTRAP_ADMIN_*` only when `identity.users` is empty.
